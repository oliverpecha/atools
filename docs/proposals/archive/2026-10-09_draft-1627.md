* **Canonical Source (`graph.toml`):** One primary persona graph serves as the central representation, while Views `02` (Swimlane Sequence), `03` (Context and Session Views), and `04` (`actl` Verification & Guard Map) are retained as generated views derived from the same `graph.toml` definition. * **Current Morphology:** The workflow operates as a deterministic spine (`actl`) orchestrating bounded loops (adversarial oracle qualification, implementation retries, escalation resolution, and closeout archivation).

### 1.3 Module-by-Module Context & Piping Blueprint



At runtime, all artifacts reside on disk and `actl` routes file pointers to each session. Saying "`actl` never interprets prose" means `actl`'s routing logic branches strictly on deterministic schema fields (enums, booleans, hashes, exit codes, counters), never on free-text strings. To prevent context rot from dead-end debugging turns while preserving end-to-end architectural intent, context lifecycles and OS UIDs are strictly partitioned:

| Module | OS UID & Context Strategy | Technical Piping & Execution Blueprint |
| --- | --- | --- |
| **`actl` (Unified Control Spine & Verifier)** | **UID `actl` / Deterministic State File (`state.json`)** | Single binary (`orchestrator` + `dispatcher` + `verifier`) running as an event-driven CLI/daemon. Communicates with the human Owner via a **Notification Adapter** (interactive terminal prompt when attached; Telegram/webhook message when detached). Whenever a human decision is required, `actl` writes `status: "hold"` to `state.json`, emits the notification (`escalation_alerts_sent++`), and exits cleanly. The Owner resumes execution via CLI (`actl resolve <sprint> ...`) or an authenticated webhook/bot reply that writes the decision `resolution` and re-invokes `actl`.

 |
| **`Architect`** | **UID `plan` / Persistent Thread (`architect_thread.jsonl` / `--resume`) + Compaction Fallback** | **Phase 1 (Interactive Q&A):** Owner converses directly with the Architect session (`sudo -u plan`) to settle product intent and ambiguities before the Architect writes `spec-v1.md` and `solution_key.patch` into `handoff/<sprint>/plan-box/` (promoted by `actl` into `actl-repo/`).

After the turn finishes, `actl` snapshots and removes `architect_thread.jsonl` (and `architect-notes.md` compaction fallback) back into `actl-repo/` so Challenger cannot read it.

| **`Challenger`** | **UID `plan` / Stateless Just-in-Time (JIT) Payload** | Fresh CLI invocation (`sudo -u plan`) per round. Retaining failed turns causes the model to anchor on prior blind spots. Before invoking Challenger, `actl` ensures `architect_thread.jsonl` is removed from `~plan/`, resets `workspaces/plan-worktree/`, and sets `plan-box/spec-vN.md` and `plan-box/solution_key.patch` to `owner: actl:plan, chmod 0440` (read-only to `plan`), leaving only `plan-box/oracle-draft/` writable (`chmod 0770`). `actl` (`dispatcher`) frontloads static cache-friendly prefixes (`[Challenger System Prompt] + [spec-vN.md] + [solution_key.patch]`) ahead of dynamic feedback (`[oracle-qual-vN.json + optional qual-review.json + prior Oracle vN]`).

Receives staged inputs from `handoff/<sprint>/ship-inputs/`: `[Archivist System Prompt] + [spec-vN.md] + [approved.diff] + [Oracle proofs/*.sh] + [context.json (closure notes[], backlog[], waived_mutants[])]` (plus `actl`/Owner rejection details if re-invoked).

### 1.4 Every Place the Workflow Reaches the Owner



1. **Phase 1 Intent Q&A (§3.2, §4.1):** Interactive `Owner ↔ Architect` conversation to establish requirements and name the sprint (`YYYY-MM-DD_<slug>`) before `spec-v1.md` is authored.


2. **Escalation & Compatibility Resolution (§5.2, §5.4, §6.1, §6.3):** When the Architect cannot resolve an escalation without changing product intent, when `mutant_waiver_authority: owner`, when `retries_archivist_exhausted` fires, when a configured `hard_cap` dimension is unsupported by the target CLI engine, or when `escalation_policy()` routes directly to the Owner.


3. **Live Run Execution & Gated Approvals (§4.3, §5.5):** When `approval_live_run: owner` is active (or via pre-authorized HMAC wrapper `/usr/local/bin/actl-live-run` when `auto | architect`), and for Phase 4 Archivation Plan review and sign-off (mandatory `approval_archivation_plan: owner`).


4. **Closeout & Merge (§3.2, §5.5):** Reviewing `diff-risk-review.md` (including any waived mutant disclosures), selecting items from `backlog-proposal.md` for the repo backlog, and executing the final `git push`.



### 1.5 Multi-Sprint Directory Architecture & 4-UID OS-Level Isolation



To enforce **`P` (Private Artifacts Unreadable)** mechanically, neutralize context-poisoning blast radii across phases, and scale cleanly across hundreds of sprints, the workspace is partitioned across **four Linux OS accounts (`actl`, `plan`, `impl`, `ship`)** with group-shared (`chmod 2770 <uid>:actl`) standalone local git clones (`workspaces/`) and a UID-partitioned POSIX IPC mailbox (`handoff/`):

* **`actl`:** Runs the deterministic `actl` control-plane binary only. Owns `actl-repo/` and `repos/target-repo/` (`chmod 700`). Zero LLM sessions or untrusted verification scripts ever execute under `actl`.


* **`plan`:** Runs Phase 1–2 planning & adversarial verification LLM sessions (`Architect`, `Challenger`), with `chmod 0440` read-only protection on `spec-vN.md` and `solution_key.patch` during Challenger turns and `architect_thread.jsonl` vaulted in `actl-repo/` between Architect turns.


* **`impl`:** Runs Phase 3 untrusted code authoring (`Implementer`).


* **`ship`:** Runs Phase 2–3 untrusted verification subprocesses inside `workspaces/actl-verify/` (followed by mandatory `sudo -u ship pkill -9 -u ship` and private `/tmp` wipe) and Phase 4 closeout curation (`Archivist`) inside `workspaces/ship-worktree/`, ensuring untrusted code during verification cannot access `actl-repo/` or leak Oracle proofs into `impl`-writable directories.

### 1.6 Resolution of Formerly Unguarded Edges



1. **Implementer → `actl` (Session Closure & Pre-Check Guards):** Guarded mechanically (**solid line**) *before* any Offline Run executes.


* **`actl` Pre-Flight Integrity Check:** `actl` (`verifier`) first verifies that the frozen `oracles/vN/` directory inside `actl-repo/` matches the immutable hash in `contract-vN.json`. A mismatch halts the runner immediately as a system integrity error (never consuming an Implementer retry).


* **Closure & Code Guards:** `actl` validates that `closure-NN.json` conforms to schema (`reason: done | blocked`, nullable `blocking_step`, `notes`, `backlog`, plus `min_attempts_before_block` and—when `solution_key_exposure: full`—`solution_key_divergence` for `reason: blocked`), natively fetches branch `wip/attempt-N` from `workspaces/wip-attempt-N/` (`chmod 2770 impl:actl`) into `workspaces/actl-verify/`, and checks `git diff <base_sha>..HEAD` against `ALLOW`/`FROZEN` scope (`scope.txt`), credential/secret leak scan, and forbidden-call lint. If any closure guard fails, `actl` emits a red `runs/ev-NN.json` citing the violated guard and routes it identically to a failed Offline Run (consuming 1 `retries_implementer` attempt and passing the guard failure in `prior_attempt.json`).




2. **Archivation Plan Hand-off (Split into Two Explicit Edges):** Because the `Archivation plan` undergoes both mechanical policy verification and semantic review, it is modeled as two separate edges:


* **Edge 1 — `Archivist → actl` (Solid Line / Script-Accepted):** `actl` enforces the precondition that `diff-risk-review.md`, `backlog-proposal.md`, and `plan/` (`NN-<slug>.patch` and `NN-<slug>.msg` pairs) exist and parse. `actl` (`verifier`) runs the deterministic regex policy check on `plan/*.msg` (subject format, required `Spec:` and `Oracle:` git trailers, matching `.patch`/`.msg` pairs, and a mandatory `Waived Mutants & Residual Risk` section in `diff-risk-review.md` if any mutant was waived), **ephemerally applies feature commits `01 .. N-1` in lexicographical order via `git apply --index && git commit -F` in `workspaces/actl-verify/` to verify 100% bit-for-bit git tree-equality against the pinned contract-hash git tag across all paths (`git diff <contract-tag> HEAD` is empty, with zero path exclusions), applies the final test-graduation commit (`NN-graduate-tests.patch`, if present) and verifies it adds strictly new files under `test/**` (`git diff --name-only --diff-filter=a <contract-tag> HEAD` is empty and all paths in `git diff --name-only <contract-tag> HEAD` match `test/**`), and executes the repo's `Test` suite as UID `ship` to confirm all existing and newly graduated tests pass**.


* **Edge 2 — `actl → Owner` (Dashed Line / Human-Accepted):** Once Edge 1 passes, `actl` sets `status: "hold"` in `state.json` and hands off the validated `Archivation plan` strictly to the human Owner (`approval_archivation_plan: owner`) for semantic review of `diff-risk-review.md`, `plan/`, and `backlog-proposal.md`. Automated rejections occur only on Edge 1 (`actl` verifier checks bounded by `retries_archivist`, escalating to the `Owner` on `retries_archivist_exhausted`). Human `Owner` revision requests on Edge 2 bypass budget limits entirely and re-invoke the Archivist with the Owner's specific change notes.

## 2. Core Vocabulary & Verification Concepts



| Term | Definition |
| --- | --- |
| **Proof** | A single executable script (`proofs/*.sh`) verifying a specific spec requirement. Exits `0` (pass) or `1` (fail). Translated into new native test files in the target repository's `test/` directory by the Archivist during Phase 4 closeout.

 |
| **Oracle** | An artifact, not an actor. A frozen, hashed directory (`oracles/vN/`) inside `actl-repo/` containing `proofs/`, `probe.sh`, `scope.txt`, `solution_key.patch`, `mutants/`, and `coverage.md`. `actl` executes it against the target codebase under isolated UID `ship`.

 |
| **Test** | The target repository's own tracked regression test suite (`test/`), including graduated proofs from prior specs. Executed automatically by `actl` (as UID `ship`) during Phase 2 `oracle-qual-vN.json`, during every Phase 3 Offline Run (after `proofs/` and `probe.sh` pass), and during Phase 4 tree verification.

 |
| **Guard** | A mechanical process check (file scope enforcement, credential leak scan, forbidden-call lint, commit message regex, git tree-equality). Proofs judge code; guards judge process.

 |
| **Actl (`actl`)** | The unified deterministic binary (`orchestrator` + `dispatcher` + `verifier`) running under UID `actl` that manages `state.json`, dispatches isolated persona sessions via `sudo -u {plan|impl|ship}`, enforces mechanical guards, and orchestrates Oracle and `Test` suite execution.

 |
| **Offline Run** | Full execution of the oracle (`proofs/` + `probe.sh` first, followed by the target repo's `Test` suite) by `actl` (running subprocesses as `sudo -u ship` inside `workspaces/actl-verify/` with private `/tmp` and post-run `pkill -9 -u ship`) after closure guards pass, with real credentials blanked.

 |
| **Live Run** | Execution of the oracle (`proofs/` + `probe.sh`) against live external services using real credentials stored strictly in the Owner's environment/secret store and injected into the black-box runner environment via `/usr/local/bin/actl-live-run`.

 |
| **Solution Key (`solution_key.patch`)** | A reference implementation patch authored solely by the Architect in Phase 1 (updated only by the Architect if Phase 2 qualification exposes a flaw), audited by the Challenger (`chmod 0440`), verified against Step 1 closure guards and Stage 2b repo `Test` during Phase 2 qualification, and copied into the Oracle directory at freeze where its canonical hash is locked. Proves satisfiability (Base = red, `solution_key.patch` = green) and serves as the Implementer's initial draft when `solution_key_exposure: full`.  |
| **Recomputation** | The oracle's end-to-end probe (`probe.sh`, Premise 5), which independently calculates claimed metrics from raw data (e.g., SQL counts, `git show --numstat`) and compares them against the implementation's output.

## 3. Personas, Authority & Independence Rules



### 3.1 Premise 7 Clarification



* **Premise 7 Formulation:** *"A persona may keep its own context across its own turns; what passes between personas is artifacts only."*

* Because Premise 7 restricts the communication channel *between* distinct personas rather than prohibiting a single persona from maintaining state across its own turns, the Architect's persistent thread (`architect_thread.jsonl`) across a spec's lifecycle is natively compliant. To preserve Premise 7 between the Architect and Challenger (which both execute under OS UID `plan`), `actl` vaults `architect_thread.jsonl` and `architect-notes.md` inside `actl-repo/` (`chmod 700 actl:actl`) whenever Challenger runs. Leaf personas (`Challenger`, `Implementer`, `Archivist`) run fresh per session under their dedicated Linux UIDs with static artifacts frontloaded by `actl` (`dispatcher`) for prompt-cache efficiency.

## 4. Standardized Artifact & Package Schemas



**Naming & Lifecycle Rules:**

* **Records** are structured data files emitted by an agent or `actl`.


* **Plans / Patches** are actionable bundles reviewed and applied during closeout.

## 5. Lifecycle Mechanics & Loop Governance



### 5.1 State Persistence, Epoch-Immutable Contract & Idempotent Transitions (`actl`)



* **External State File (`specs/<sprint>/runs/state.json`) vs. Epoch-Immutable `contract-vN.json`:** `actl` (`orchestrator`) initializes `state.json` at the start of Phase 1 (scoped to `run_id` across any `Spec vN` revisions) to track runtime counters (`retries_oracle`, `retries_implementer`, `retries_archivist`, active stage, `active_contract`, `status`, and any dynamic retry increments granted during escalations). `contract-v1.json` is minted **once** at Oracle `v1` freeze (entering Phase 3) and is never mutated:


* If additional retries are granted on escalation (`action: "grant_retries"`) without changing the spec or oracle, `state.json` and `escalation-NN.json` (`resolution`) are updated while `contract-v1.json` remains static.


* If an escalation updates `spec-vN.md`, `scope.txt`, or `oracles/vN/` (`action: "update_oracle"`), `actl` re-qualifies the updated Oracle via `oracle-qual-vN+1.json`, mints `contract-vN+1.json` (which resets `retries_implementer` to the new contract's baseline budget, requiring `retries_granted: 0` in `resolution`), and regenerates the requirement rows (`R_i`) of `checklist.md` from `oracles/vN+1/coverage.md` with `Offline Run` and `Live Run` reset to `open` (while preserving any `mutant/*.patch | waived` rows).


* If `state.json` is lost or corrupted, all counters, active contract epochs, and grants can be deterministically reconstructed from `runs/oracle-qual-v*.json`, `runs/ev-*.json`, `escalation-NN.json` (via `resolution.retries_granted` and `minted_contract`), and the extended `sessions.tsv` ledger (`model`, `turns`, `tool_calls`, `tokens`, `cost_usd`, `accepted_items`, retry counters, `escalation_alerts_sent`).




* **Idempotent Write-Ahead Transitions:** Every state transition is idempotent, keyed by `(run_id, transition_id, attempt)` (and including `contract_hash` from Phase 3 onward), and writes a `"started"` marker to `state.json` *before* launching a process or sending an alert.


* If `actl` crashes after launching an agent session, a restarted `actl` detects the `"started"` marker and does not launch a duplicate session or double-spend the budget.


* Similarly, during an Owner `hold` wait, idempotency prevents sending duplicate escalation alerts.





### 5.2 Adversarial Oracle Qualification Loop (`Architect ↔ actl ↔ Challenger`)



1. **Adversarial Authoring & Mechanical Qualification:**

* **Architect Spec & Reference Key:** In Phase 1, following interactive Q&A with the Owner, the Architect (`sudo -u plan`) authors `spec-v1.md` and `solution_key.patch`. `actl` snapshots `architect_thread.jsonl` into `actl-repo/` and sets `spec-v1.md` and `solution_key.patch` in `plan-box/` to `chmod 0440` (`actl:plan`).


* **Challenger Audit & Oracle Authoring:** In Phase 2, the cross-family Challenger (`sudo -u plan`) audits `spec-v1.md` and `solution_key.patch` for semantic flaws (missing requirement coverage, shared misreadings, weak assertions such as checking `has("email")|not` when an email leaks under a renamed key `contact`) and authors `oracles/v1/` (`proofs/`, `probe.sh`, `mutants/`, `scope.txt`, `coverage.md`) inside `plan-box/oracle-draft/`. By default, `scope.txt` sets `FROZEN: test/**`.


* **Mechanical Qualification (`oracle-qual-vN.json`):** `actl` (`verifier`) runs `oracles/vN/` inside `workspaces/actl-verify/` (executing test subprocesses under UID `ship` against `base_sha`), verifying that:


1. The null base implementation at `base_sha` fails `proofs/` (`null_base: red`),


2. `solution_key.patch` passes Step 1 Closure Guards (`scope.txt`, secret scan, forbidden-call lint) (`solution_key_guards: green`),


3. `solution_key.patch` passes `proofs/` and `probe.sh` repeatedly (`solution_key_green: 3/3`),


4. `solution_key.patch` passes Stage 2b (the target repo's existing `Test` suite) (`solution_key_repo_test: green`)—if the spec intentionally alters existing tested behavior, this check catches the obsolete test in Phase 2 so the Architect can update `solution_key.patch` and the Challenger can surgically add `ALLOW: test/<specific_file>` to `scope.txt`, and


5. All `mutants/*.patch` are killed (`killed: true`, exit `1`).






2. **Four-Layer Defense Against Weak Proofs:**

* *Value-level sentinel proofs:* Seed known sentinel strings (e.g., a test email) and fail if the literal string appears anywhere in the raw response payload.


* *End-to-end probe (`probe.sh`):* Inspects actual runtime outputs and performs independent recomputation.


* *Adversarial mutants:* Challenger supplies sabotaged patches (`mutants/contact_leak.patch`) that expose weak assertions and remain archived in `oracles/vN/mutants/` for future verification.


* *Visible residual risk & Owner disclosure:* Any surviving mutant (`killed: false`) waived at escalation (recorded in `escalation-NN.json` `resolution.waived_mutants`) is stamped as a dedicated `mutant/<name>.patch | waived | escalation-NN` row in `checklist.md` and must be explained in `diff-risk-review.md` for Owner review at closeout.




3. **Deterministic Convergence & `retries_oracle_exhausted` Resolution:**

* **Immediate Freeze on Green `oracle-qual-vN.json`:** If `oracle-qual-vN.json` passes completely (`null_base: red`, `solution_key_guards: green`, `solution_key_green: 3/3`, `solution_key_repo_test: green`, all mutants `killed: true`), `actl` freezes the Oracle immediately (locking the canonical hash of `solution_key.patch`) and mints `contract-v1.json`.


* **Deterministic Two-Branch Routing on Red `oracle-qual-vN.json` (`v2`, `v3`):** When `oracle-qual-vN.json` is red and `retries_oracle` budget remains, `actl` branches mechanically on the qualification fields:


1. **Branch A — Pure Oracle Failure** (`solution_key_guards == "green"` AND `solution_key_green == "3/3"` AND `solution_key_repo_test == "green"`, while `null_base == "green"` OR any mutant has `killed: false`): `actl` dispatches **Challenger** directly (`retries_oracle++`) to strengthen `proofs/` or fix the mutant.


2. **Branch B — Solution-Key Conflict** (any `solution_key_*` check is red): `actl` dispatches **Architect** first (restoring `architect_thread.jsonl` and write access to `spec-vN.md`/`solution_key.patch`) to inspect `oracle-qual-vN.json` and `oracle-draft/`. The Architect either updates `spec-vN.md` / `solution_key.patch` (if the key was flawed) or writes a structured directive in `plan-box/qual-review.json` (if the Challenger's proof or `scope.txt` was over-strict), after which `actl` re-locks `spec-vN.md`/`solution_key.patch` (`chmod 0440`), automatically dispatches **Challenger** to align `oracle-draft/`, and runs `oracle-qual-vN+1.json` (counting as 1 full `retries_oracle` round).




* **When `retries_oracle` Runs Out (`trigger: retries_oracle_exhausted`):** `actl` assembles `escalation-NN.json` (with `oracle_review` populated from the latest `oracle-qual-vN.json`, including `failing_checks` and `surviving_mutants`) and routes it via `actl → Architect` (or `actl → Owner` if `mutant_waiver_authority: owner`). The authority records its decision in `escalation-NN.json` (`resolution`), choosing one of three actions:


1. Grant additional `retries_oracle` budget in `state.json` (`action: "grant_retries"`).


2. Write the next oracle version (`oracles/vN/`) directly (`action: "update_oracle"`, re-verified by `oracle-qual-vN.json`).


3. Waive the surviving mutant(s) (`action: "waive_mutant"`, governed by `mutant_waiver_authority: architect | owner`, default `architect`), which `actl` mechanically accepts **only when `oracle_review.failing_checks` is empty** (`null_base == "red"` and all `solution_key_* == "green"`): the latest oracle freezes, `actl` mints `contract-v1.json` (stamping `minted_contract`), and appends `mutant/<name>.patch | waived | escalation-NN (sha256: ...)` rows in `checklist.md`.







### 5.3 Coverage Map & Checklist Stamping Rule



* `coverage.md` explicitly lists every proof ID (plus `probe.sh`) required to satisfy each requirement (`R_i → [proof_a, proof_b, ..., probe.sh]`).


* `specs/<sprint>/checklist.md` tracks `Offline Run` and `Live Run` receipts in separate columns:


* When `live_run: none`, the `Live Run` column is initialized to `n/a`, and `actl` stamps each `R_i` row `Status: done` once all mapped `proofs/`, `probe.sh`, and the target repo's `Test` suite exit `0` (`green`) in the composite `Offline Run` receipt (`ev-NN.json`) against the **exact same `head` commit SHA** (pinned by the contract-hash git tag).


* When `live_run: required`, `Status` remains `open` after the `Offline Run` column is populated and only flips to `done` when the `Live Run` column also records `0` (`green`) receipts for all mapped `proofs/` and `probe.sh` on the **identical `head` commit SHA**.


* Surviving mutants waived in Phase 2 occupy their own `mutant/<name>.patch | waived | escalation-NN` rows and **never** mark a requirement row (`R_i`) as `done` or `waived`.


* Closeout requires **zero `open` requirement rows** in `checklist.md` (every `R_i` row must be `done`, and any waived mutant rows must be disclosed in `diff-risk-review.md`).





### 5.4 Implementation Routing, Retries & Blocked Escalations (Settled)



1. **Standalone Clone & Retry / Restart Mechanics:** For each attempt $N$, `actl` (`dispatcher`) creates a fresh standalone local clone (`git clone --local --no-hardlinks repos/target-repo workspaces/wip-attempt-N`, owned by `impl:actl`, `chmod 2770`) checked out at `base_sha` on branch `wip/attempt-N`, and launches a fresh Implementer session (`sudo -u impl`, frontloading static prefixes + `solution_key.patch` when `full`). The Implementer is instructed to commit her work incrementally onto `wip/attempt-N` for full traceability. When the Implementer writes `closure-NN.json`, `actl` (`verifier`) natively fetches `wip/attempt-N` into `workspaces/actl-verify/` (`owner: ship:actl, chmod 2770`) to evaluate closure guards and the Offline Run. When an `actl` closure guard or Offline run is red and `retries_implementer` budget remains, `actl` deletes `workspaces/wip-attempt-N/`, creates a clean standalone clone `workspaces/wip-attempt-N+1/` at `base_sha`, and writes `prior_attempt.json` (previous diff patch, `failing_step` and `failing_line` from the last `ev-NN.json`, and attempt count) to `handoff/<sprint>/work-order/` strictly as an optional hint. `log_tail` from Escalation records goes to the Architect only and is never forwarded to a later Implementer.


2. **Deterministic Routing on Closure `reason`:**

* `reason: done` → Triggers `actl` **Step 1 Pre-Flight & Closure Guards** followed immediately by the **Step 2 Fail-Fast Offline Run**.


* `reason: blocked` *(Consolidates former `blocked` and `dispute`)* → Implementer halts when it cannot satisfy `actl` verification due to an `ALLOW` scope restriction (including an obsolete existing test in `FROZEN: test/**`), missing architectural decision, or suspected over-constrained proof (`blocking_step` cites the deterministic `steps[].cmd` ID from `ev-NN.json`, e.g., `"guard:scope"`, `"bash proofs/02_no_email.sh"`, or `"test:<name>"`, or `null` on a pure architectural block).


* **Anti-Early-Give-Up Guards:** Defining `attempts = 1 + count(prior ev-NN for active contract)`, `actl` mechanically rejects `reason: blocked` (treating an invalid `blocked` claim as a failed attempt that consumes 1 `retries_implementer` credit) unless:


1. `attempts >= min_attempts_before_block` and at least one prior failed `ev-NN.json` exists on the active `contract-vN.json`,


2. all Step 1 mechanical `ALLOW`/secret/lint closure guards pass (unless `blocking_step == "guard:scope"`) and the target repository's own compilation and `Test` suite pass in the offline sandbox (unless `blocking_step` explicitly cites a failing `test:<name>` step from `ev-NN.json`), and


3. **when `solution_key_exposure: full**`, `closure-NN.json` includes a non-empty `solution_key_divergence` identifying the specific un-asserted `spec-vN.md` requirement or architectural constraint that `solution_key.patch` shortcutted (since `solution_key.patch` already passed `oracle-qual-vN.json` in Phase 2).




* **Phase 3 Obsolete-Test Escape Hatch (`FROZEN: test/**`):** If an existing regression test in `test/**` fails during Phase 3 because it conflicts with new spec behavior and was not unfrozen in Phase 2, the Implementer cannot edit `test/**` directly (`FROZEN: test/**`). Instead, the Implementer halts with `reason: blocked` and `blocking_step: "test:<name>"`. `actl` routes `escalation-NN.json` (`trigger: blocked`) to the Architect, who inspects the test failure and resolves via `action: "update_oracle"`—surgically adding `ALLOW: test/<specific_file>` to `oracles/vN+1/scope.txt`, re-qualifying via `oracle-qual-vN+1.json`, and minting `contract-vN+1.json`.


* **Escalation Routing:** Once `blocked` preconditions are met, `actl` assembles `escalation-NN.json` (`trigger: blocked`, citing `last_closure` and `evidence`) and routes it via `actl → Architect`. The Architect inspects `escalation-NN.json` in its persistent thread and records `resolution` in `escalation-NN.json`: either (a) updates `scope.txt` / `Spec vN` / `Oracle vN` (`action: "update_oracle"`, `retries_granted: 0`, re-qualified via `oracle-qual-vN+1.json`, minting `contract-vN+1.json` for a new contract epoch and resetting `checklist.md` requirement rows to `open`), (b) rejects the block and grants additional `retries_implementer` budget in `state.json` (`action: "grant_retries"`), or (c) escalates to the human `Owner` via `actl → Owner` (`status: "hold"`) if product intent must change.


* *Intra-Session Hard-Cap Termination (`trigger: hard_cap_exhausted`):* If a session is killed by the wall-clock supervisor (`timeout -k 15s`) or supported turn/token/cost hard caps, `actl` synthesizes `escalation-NN.json` (`trigger: hard_cap_exhausted`) from `state.json` and routes it via `actl → Architect`.





### 5.5 Closure Guards, Fail-Fast Offline Run, Live Run & Archivation Sequence (Settled)



1. **Step 1 — `actl` Pre-Flight & Self-Tested Mechanical Closure Guards (Before Offline Run):**

* **Oracle Pre-Flight Hash Check:** `actl` (`verifier`) verifies `actl-repo/specs/<sprint>/oracles/vN/` against `contract-vN.json` (halting on corruption without consuming an Implementer retry).


* **Closure Guards:** Upon `Implementer → actl` closure, and *before* executing untrusted Implementer code, `actl` validates `closure-NN.json`, fetches `wip/attempt-N` into `workspaces/actl-verify/`, checks `git diff <base_sha>..HEAD` against `ALLOW`/`FROZEN` scope (`scope.txt`), runs the credential/secret leak scan, and runs the forbidden-call lint.


* **Mandatory Self-Tests:** Every guard/scanner must pass its own built-in self-test (verifying it catches known synthetic leaks and forbidden calls) before evaluating the worktree so a broken lint cannot silently pass under `approval_live_run: auto`.




2. **Step 2 — Fail-Fast Offline Run (`proofs/` First, Repo `Test` Second, Executed as UID `ship`):**


Once Step 1 guards are green, `actl` checks out the candidate commit in `workspaces/actl-verify/` (`owner: ship:actl, chmod 2770`) and spawns the verification runner as `sudo -u ship` with a private `/tmp` (`unshare -p --kill-child` / `PrivateTmp=yes`) and credentials blanked:


* **Stage 2a (Fast Feature Check):** Executes the Oracle's `proofs/*.sh` and `probe.sh` first so feature errors fail fast within seconds.


* **Stage 2b (Regression Armor):** Immediately executes the target repository's existing `Test` suite (`test/`) to guarantee zero regressions against prior specs.


* **Post-Run Cleanup:** Regardless of exit code, `actl` runs `sudo -u ship pkill -9 -u ship` and wipes the private `/tmp` so no background process spawned during testing survives into later runs or Phase 4.
* When both Stage 2a and Stage 2b exit `0`, `actl` writes the composite green `runs/ev-NN.json` (`steps[]`) and stamps the `Offline Run` column in `checklist.md`.




3. **Step 3 — Live Run (Before Archivist):** Governed by `live_run: none | required` and `approval_live_run: auto | architect | owner`. **`approval_live_run: auto | architect` means the Owner pre-authorized the live run via an Owner HMAC signature in `contract-vN.json`; `actl` invokes the root-owned wrapper `sudo -u owner /usr/local/bin/actl-live-run <sprint>`, which verifies the Owner HMAC on `contract-vN.json`, loads the Owner's live `.env`, and injects live credentials strictly into the black-box `proofs/*.sh` and `probe.sh` runner environment (or staging service environment)—never into an untrusted `impl` process or `actl` storage**. When `approval_live_run: owner`, `actl` sets `status: "hold"` and notifies the Owner to trigger the Live Run directly. When green, `actl` stamps the `Live Run` column and marks requirement rows `Status: done` in `checklist.md`.


4. **Step 4 — Archivist Curation & Proof-to-Test Graduation:**

* Once Steps 1–3 are green and zero `open` rows remain in `checklist.md`, `actl` pins the approved state via an internal git tag in `repos/target-repo/.git` **keyed by `contract-vN.json` hash**, stages `spec-vN.md`, `approved.diff`, `oracles/vN/proofs/*.sh`, and `context.json` (`notes[]`, `backlog[]`, and `waived_mutants[]` from `escalation-NN.json`) into `handoff/<sprint>/ship-inputs/` (`chmod 750`, `actl:ship`), initializes standalone clone `workspaces/ship-worktree/` (`chmod 2770 ship:actl`) at `<contract-tag>`, and invokes the Archivist (`sudo -u ship`).


* The Archivist consumes `ship-inputs/` to author `diff-risk-review.md` (including a mandatory `Waived Mutants & Residual Risk` section if any mutant was waived) and craft ordered patch/message pairs (`plan/NN-<slug>.patch` and `plan/NN-<slug>.msg`).


* The Archivist merges the Implementer's `backlog` items with its own candidates into `backlog-proposal.md` (containing `none` if empty).


* **Proof-to-Test Graduation (Strictly New Test Files):** Because any necessary updates to *existing* tests were already completed during Phase 2/3 and locked into `<contract-tag>`, the Archivist never touches existing test files. The Archivist translates the black-box `proofs/*.sh` into **new** native repository test files inside `test/**` as a dedicated final commit (`plan/NN-graduate-tests.patch` + `.msg`)—or omits `NN-graduate-tests.patch` if commits `01..N-1` already added native tests covering all proofs.




5. **Step 5 — Closeout Policy, 100% Feature Tree-Equality & `--diff-filter=a` `Test` Check, Approval & Owner Push:**

* **Solid Edge (`Archivist → actl`):** `actl` verifies all required files exist in `handoff/<sprint>/archivation-plan/`, runs the regex policy check on `plan/*.msg` and `diff-risk-review.md`, **ephemerally applies feature commits `01 .. N-1` in lexicographical order via `git apply --index && git commit -F` in `workspaces/actl-verify/` and verifies 100% bit-for-bit git tree-equality between the resulting tree and `<contract-tag>` across all paths (`git diff <contract-tag> HEAD` is empty, zero path exclusions), applies commit `N` (`NN-graduate-tests.patch`, if present) and verifies it contains strictly newly added files under `test/**` (`git diff --name-only --diff-filter=a <contract-tag> HEAD` is empty and all paths in `git diff --name-only <contract-tag> HEAD` match `test/**`), and executes the repo's `Test` suite as UID `ship` to prove all existing and newly graduated tests pass**.


* **Dashed Edge (`actl → Owner`):** Governed strictly by `approval_archivation_plan: owner` (`architect` and `auto` approval are retired). Once Edge 1 mechanical checks pass, `actl` marks `status: "hold"` in `state.json` and notifies the Owner via the Notification Adapter. If Edge 1 fails, `actl` loops back to the Archivist bounded by `retries_archivist` (escalating to the `Owner` on `retries_archivist_exhausted`). If the Owner requests changes on Edge 2, revisions loop back to the Archivist uncapped by budget counters.


* **Final Commit, Backlog Storage & Push:** Once approved, `actl` applies the verified `plan/NN-<slug>.patch` + `.msg` commit chain (feature commits + graduated `test/` commit) to `repos/target-repo/`, commits the final stamped `specs/<sprint>/checklist.md` to `actl-repo` (`runs/ev-*.json` remain untracked), presents `backlog-proposal.md` items for the **Owner** to curate into the repo backlog, and the human **Owner pushes** to remote trunk.

## 6. Dynamic Budget & Escalation Functions



### 6.1 Intra-Session Hard Caps (`hard_cap`) vs. Inter-Session Loop Counters (`retries_*`)



Resource and iteration ceilings are partitioned into two distinct classes resolved at Phase 1 start into `state.json` and locked into `contract-vN.json` at Phase 3 Oracle freeze:

```text
effective_limit(dimension, contract_or_state, context) -> (limit, mechanism, on_exceed)

```

1. **Intra-Session Hard Caps (`hard_cap` → triggers `hard_cap_exhausted`):**

* Govern a **single CLI invocation**: `wall_clock` (`timeout -k 15s <limit>`), `turns`, `tool_calls`, `tokens`, and `cost_usd`.


* **Native Enforcement & Fail-Closed Compatibility Halt (MVP):** Whenever a CLI engine natively supports a configured `hard_cap` dimension, `dispatch.py` passes and enforces the native flag directly. If a contract or configuration specifies a non-null `hard_cap` dimension (e.g., `turns`, `tool_calls`, `tokens`, or `cost_usd`) and the target persona's CLI adapter cannot confirm native enforcement support, **`actl` refuses to start the session (fail-closed), writes `status: "hold"` to `state.json`, and notifies the Owner/user identifying the exact unsupported `(cli_engine, dimension)` pair** so the user can either set that dimension to `null` (relying on `wall_clock` + post-run `sessions.tsv` telemetry) or switch the persona's CLI engine.


* **Post-MVP Roadmap Note (Stream-Parsed Hard Caps):** In a post-MVP release, `dispatch.py` will add real-time JSONL/stdout stream monitoring to enforce `turns`, `tool_calls`, `tokens`, and `cost_usd` via `SIGTERM`/`SIGKILL` across CLI engines that lack native flags without halting on startup.
* **Sub-Agent Spawner Prohibition:** Every CLI adapter mechanically disables native in-process sub-agent tools (`AgentTool` / sub-task spawners) so no persona can spawn an in-process child agent inside the same UID. Every persona transition must return to `actl`.


* **Universal Wall-Clock Supervisor:** Every CLI engine retains the external `sudo -u {plan|impl|ship} timeout -k 15s <limit>` wrapper as the mandatory hard wall-clock kill switch.




2. **Inter-Session Loop Counters (`retries_<stage>` → triggers `retries_<stage>_exhausted`):**

* Govern multi-session state machine loops tracked in `state.json`:


* `retries_oracle` → `retries_oracle_exhausted` (Phase 2 `Architect ↔ actl ↔ Challenger` qualification loop).


* `retries_implementer` → `retries_implementer_exhausted` (Phase 3 `Implementer ↔ actl` implementation loop, paired with `min_attempts_before_block`).


* `retries_archivist` → `retries_archivist_exhausted` (Phase 4 automated `actl` mechanical rejections on Edge 1; human Owner revisions on Edge 2 are uncapped).

### 6.3 Dynamic Escalation Policy Function



Escalation routing resolves dynamically across all four phases (reading `state.json` in Phases 1–2 and `contract-vN.json` + `state.json` in Phases 3–4):

```text
escalation_policy(event, contract_or_state, context) -> decision (logged with inputs)

```

* **Inputs:** Event type (`retries_oracle_exhausted`, `retries_implementer_exhausted`, `retries_archivist_exhausted`, `hard_cap_exhausted`, `blocked`), risk tier, `mutant_waiver_authority`, time of day, and Owner availability.


* **Two-Tier Routing (`actl → Architect` then `actl → Owner`):** By default, `actl` routes `retries_oracle_exhausted`, `retries_implementer_exhausted`, `hard_cap_exhausted`, and `blocked` to the **Architect** first. `actl` routes directly to the human **Owner** (via the Notification Adapter) when:


1. The Architect explicitly escalates an unresolved spec/scope/mutant decision to the Owner (`resolution.action: "escalate_owner"`),


2. The synchronous Architect session itself fails or hits `hard_cap_exhausted`,


3. `retries_archivist_exhausted` triggers in Phase 4,


4. An unsupported `(cli_engine, hard_cap_dimension)` pair triggers the fail-closed adapter guard on startup, or


5. `escalation_policy()` requires direct Owner authority (e.g., `mutant_waiver_authority: owner` or high risk tier).




* **Safe Default on No Response (`hold`):** Availability windows, time-of-day routing, and `escalation_alerts_sent` apply strictly when targeting the human **Owner**. If an Owner escalation receives no response within the availability window (or if a synchronous Architect invocation fails), the mandatory safe default is **`hold` (write `status: "hold"` in `state.json` and await human Owner intervention)—never auto-approve**.


* **Hold scope:** `hold` applies strictly to the actionable party's decision; an unanswered informational Owner notification never blocks a run that the Architect is authorized to resolve.
