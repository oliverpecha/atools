# Agent Graph Architecture & Governance Specification

**Date:** October 10, 2026 20:05

**Overview:** This specification defines the graph topology, 4-UID POSIX kernel isolation model, persona responsibilities, artifact schemas, verification gates, and lifecycle governance for the `actl` multi-agent software delivery system.

## 1. Graph Topology, Visual Semantics & Workspace Isolation

### 1.1 Single Source of Truth & Generated Views

* **Canonical Source (`graph.toml`):** One primary persona graph serves as the central representation, while Views 02 (Swimlane Sequence), 03 (Context and Session Views), and 04 (`actl` Verification & Guard Map) are generated deterministically from the same `graph.toml` definition. View 04 functions as an annotation layer over the persona graph rather than an independent topology.


* **Primary Deliverable:** Raw `.mmd` Mermaid definitions are the canonical visual artifacts (rendered at full resolution via `mermaid-cli` or native Markdown viewers).


* **Workflow Topology:** The workflow operates as a deterministic spine (`actl`) orchestrating bounded loops (adversarial oracle qualification with Architect lock authority, implementation retries, live run gating and recovery, escalation resolution, and closeout archivation).


* **Escalation edges in the graph:** `actl` → Architect (never drawn through the Implementer) carries the Escalation record for `retries_oracle_exhausted`, `retries_implementer_exhausted`, `live_run_failed`, `hard_cap_exhausted`, and `blocked`. A secondary `actl` → Owner control edge activates when the Architect escalates to the human Owner, fails/times out, on `retries_live` exhaustion, on `retries_archivist_exhausted`, on unsupported `hard_cap` CLI flags, or when `escalation_policy()` targets the Owner directly.



### 1.2 Orthogonal Edge Semantics

Every edge in the graph is classified along two independent axes: acceptance verification (line style) and routing role (color or arrowhead).

| Axis | Visual Encoding | Classification & Mechanics |
| --- | --- | --- |
| **Axis 1: Who Accepts the Hand-off (Verification)** | **Solid Line** | **Deterministic / Objective:** Accepted or enforced by `actl` via mechanical checks that inspect the transfer and reject violations (e.g., JSON schema validation on an LLM-written closure report, `git diff` scope checks, regex, git tree-equality, legacy test function count checks, and mutant-kill checks on commit plans, deterministic session invocation).

 |
| **Axis 1: Who Accepts the Hand-off (Verification)** | **Dashed Line** | **Probabilistic / Subjective:** Accepted by an LLM or human exercising judgment (e.g., Architect ↔ Challenger spec/oracle review and lock decision, Architect or Owner Live Run approval, `actl` → Owner archivation judgment). Represented as dashed lines because human review and semantic quality rely on judgment rather than mechanical verification.

 |
| **Axis 2: What Travels (Routing Role)** | **Standard Arrowhead / Primary Color** | **Unmodified Artifact Flow (Persona → Persona):** Visually represents an artifact authored by one persona (`spec-vN.md`, Oracle vN) whose file pointer is staged and handed unmodified to the next persona when scheduled by `actl`.

 |
| **Axis 2: What Travels (Routing Role)** | **Open Arrowhead / Distinct Control Color** | **Control & Synthesized Envelope Flow (`actl` → Persona):** Scheduling signals and pointers to `actl`-synthesized JSON envelopes (`contract-vN.json`, Work order, `escalation-NN.json`). Because `actl` invokes sessions deterministically via script, control edges are drawn as solid lines (distinguished by their open arrowhead and control color, never dashed).

### 1.3 Module-by-Module Context & Piping Blueprint

At runtime, all artifacts reside on disk and `actl` routes file pointers to each session. `actl` never interprets free-text prose; its routing logic branches strictly on deterministic schema fields (enums, booleans, hashes, exit codes, counters). Process lifecycle supervision, state tracking, and console I/O are decoupled via daemonized headless `tmux` sessions backed by `systemd` user lingering (`loginctl enable-linger`):

| Module | OS UID & Context Strategy | Technical Piping & Execution Blueprint |
| --- | --- | --- |
| **`actl` (Unified Control Spine & Verifier)** | `UID actl` (in supplementary groups `plan`, `impl`, `ship`) / Deterministic State File (`state.json`) + `tmux` Supervisor Registry | Single deterministic binary (`actl-repo/bin/actl`) composed of three internal modules—`orchestrator` (`state.py`), `dispatcher` (`dispatch.py`), and `verifier` (`verify.py`)—running as an event-driven CLI/daemon. Spawns agent sessions inside detached headless `tmux` sessions (`spawn_detached_session`) with ephemeral `{session}.run.sh` scripts (`umask 0007`, `trap cleanup EXIT`, `remain-on-exit off`) and tracks liveness dynamically via `list_active_tmux_sessions()`. Interactive attachment (`actl attach {session}`) uses a non-destructive `pipe-pane` streaming tail proxy (`stream_session`). Communicates with the human Owner via a Notification Adapter (terminal prompt when attached; Telegram/webhook when detached), writing `status: "hold"` to `state.json` whenever a human decision is required.

 |
| **Architect** | `UID plan` / Persistent Thread (`architect_thread.jsonl` / `--resume`) + Compaction Fallback | **Phase 1 (Interactive Q&A):** Owner converses directly with the Architect session (`sudo -u plan`) to settle product intent and ambiguities (and sign `live-delegation.hmac` if `approval_live_run: architect`) before the Architect writes `spec-v1.md` and `solution_key.patch` into `handoff/{sprint}/plan-box/`. After every Architect turn, `actl` vaults `architect_thread.jsonl` and `architect-notes.md` into `actl-repo/`, promotes `spec-vN.md` and `solution_key.patch` to `actl-repo/`, `unlink()`s the `plan`-owned originals in `plan-box/`, and writes fresh copies owned by `actl:plan` (`chmod 0440`) inside `chmod 0750 plan-box/`.

<br>

<br>

<br>**Phase 2 (Oracle Review & Lock Authority):** When `actl` finishes running `oracle-qual-vN.json` on the Challenger's draft Oracle, `dispatch.py` restores `architect_thread.jsonl` and `chmod 0770` on `plan-box/`. The Architect reviews the Challenger's `oracle-critique.md` and `oracle-qual-vN.json` (which flags diagnostic cases `pure_oracle_failure` or `solution_key_conflict`) and writes `plan-box/oracle-decision.json` (`decision: "lock_oracle"` | `"revise_oracle"`, optionally updating `spec-vN.md`, fixing `solution_key.patch` directly without wasting a Challenger retry, or surgically widening `ALLOW` in `scope.txt`).

<br>

<br>

<br>**Phase 3 (Live Run Gate & Escalation Resolution):** Reviews candidate diffs (`git diff {base_sha}..{head_sha}`) for Live Run approval (`plan-box/live-decision.json`: `"approve_live"` | `"reject_live"` when `approval_live_run: architect`) and resolves `escalation-NN.json` packets (`grant_retries`, `waive_mutant`, `update_scope`, `reopen_oracle`, `escalate_owner`), including `live_run_failed` recovery up to `retries_live`.

 |
| **Challenger** | `UID plan` / Stateless Just-in-Time (JIT) Payload | Fresh CLI invocation (`sudo -u plan`) per round. Retaining failed turns causes the model to anchor on prior blind spots. Before invoking Challenger, `actl` ensures `architect_thread.jsonl` is removed from `~plan/`, resets `workspaces/plan-worktree/` via `sudo -u plan`, and verifies `plan-box/` is `0750 actl:plan` with `spec-vN.md` and `solution_key.patch` owned by `actl:plan` (`chmod 0440`—preventing `chmod`, modification, and POSIX `unlink()` replacement by `UID plan`), leaving only `plan-box/oracle-draft/` writable (`chmod 0770`). `actl` frontloads static cache-friendly prefixes (`[Challenger System Prompt] + [spec-vN.md] + [solution_key.patch]`) ahead of dynamic feedback (`[oracle-qual-vN.json + oracle-decision.json + prior Oracle vN]`).

 |
| **Implementer** | `UID impl` / Stateless Just-in-Time (JIT) Payload | Fresh CLI invocation (`sudo -u impl`) per attempt inside a clean `workspaces/wip-attempt-N/` standalone local git clone (`sudo -u impl git clone --local --no-hardlinks`, `owner: impl:actl`, `chmod 2770`, `umask 0007`) checked out at `base_sha` on branch `wip/attempt-N`. `~impl` is provisioned read-only (`root:impl`, `chmod 0750`). `actl` frontloads static files (`[Implementer System Prompt] + [spec-vN.md] + [contract-vN.json] + [solution_key.patch when full]`) ahead of dynamic retry feedback (`[prior_attempt.json]`) to maximize prompt-cache hits without dragging failed tool call noise.

 |
| **Archivist** | `UID ship` / Stateless Just-in-Time (JIT) Payload | Invoked strictly in Phase 4 (`sudo -u ship`) inside `workspaces/ship-worktree/` (`owner: ship:actl`, `chmod 2770`, `umask 0007`) after the Implementer has passed all Phase 3 Offline and Live runs. Receives staged inputs from `handoff/{sprint}/ship-inputs/`: `[Archivist System Prompt] + [spec-vN.md] + [approved.diff] + [Oracle proofs/*.sh] + [non-applying mutants/*.patch requiring rebase] + [context.json (closure notes[], backlog[], waived_mutants[], modified_legacy_tests_diff)]` (plus `actl`/Owner rejection details if re-invoked).

### 1.4 Every Place the Workflow Reaches the Owner

1. **Phase 1 Intent Q&A (§3.2, §4.1):** Interactive Owner ↔ Architect conversation to establish requirements, name the sprint (`YYYY-MM-DD_{slug}`), and—when `approval_live_run: architect`—sign the sprint-level `live-delegation.hmac` token before `spec-v1.md` is authored.


2. **Escalation, Live Failure & Compatibility Resolution (§5.2, §5.4, §5.5, §6.1, §6.3):** When the Architect cannot resolve an escalation without changing product intent, when `mutant_waiver_authority: owner`, when `retries_live` or `retries_archivist_exhausted` fires, when a Live Run fails (parallel non-blocking alert on first failure; blocking `hold` if `retries_live` is exhausted), when a configured `hard_cap` dimension is unsupported by the target CLI engine, or when `escalation_policy()` routes directly to the Owner.


3. **Live Run Execution & Gated Approvals (§4.3, §5.5, §5.6):** When `approval_live_run: owner` is active (Owner signs `live-decision.hmac` on `head_sha`; or pre-authorized via `live-delegation.hmac` + Architect's `live-decision.json` when `approval_live_run: architect`), and for Phase 4 Archivation Plan review and sign-off (mandatory `approval_archivation_plan: owner`).


4. **Closeout & Merge (§3.2, §5.6):** Reviewing `diff-risk-review.md` (including any `Waived Mutants & Residual Risk` and `Modified Legacy Tests` disclosures), selecting items from `backlog-proposal.md` for the repo backlog, and executing the final `git push`.



### 1.5 Multi-Sprint Directory Architecture & 4-UID OS-Level Isolation

To enforce **P (Private Artifacts Unreadable)** mechanically, neutralize context-poisoning blast radii across phases, and scale cleanly across hundreds of sprints, the workspace is partitioned across four Linux OS accounts (`actl`, `plan`, `impl`, `ship`) where `actl` is a member of groups `plan`, `impl`, and `ship`. All standalone local git clones (`workspaces/`) are created and wiped via `sudo -u {role_uid}` with `umask 0007` and `chmod 2770 {role_uid}:actl`, paired with a UID-partitioned POSIX IPC mailbox (`handoff/`):

* **`actl`:** Runs the deterministic `actl` control-plane binary only. Owns `actl-repo/` and `repos/target-repo/` (`chmod 700`). Zero LLM sessions or untrusted verification scripts ever execute under `actl`.


* **`plan`:** Runs Phase 1–2 planning & adversarial oracle sessions (Architect, Challenger), plus Phase 2 `oracle-qual-vN.json` test execution inside `workspaces/actl-verify/`. Before Challenger turns, `actl` `unlink()`s `plan`-owned files in `plan-box/` and writes fresh `actl:plan` (`chmod 0440`) copies of `spec-vN.md` and `solution_key.patch` inside `chmod 0750 plan-box/`, while `architect_thread.jsonl` is vaulted in `actl-repo/`.


* **`impl`:** Runs Phase 3 untrusted code authoring (Implementer) in `workspaces/wip-attempt-N/` and Phase 3 test verification inside `workspaces/actl-verify/` (followed by mandatory `sudo -u impl pkill -9 -u impl` and private `/tmp` wipe). `~impl` is read-only (`root:impl`, `chmod 0750`), and `handoff/{sprint}/closures/` is locked to `chmod 0750` during verification so `UID impl` has zero persistent writable paths across runs. `actl` temporarily stages a copy of `oracles/vN/` for verification execution and deletes it immediately after the run so `actl-repo/` remains `chmod 700`.


* **`ship`:** Exclusively runs Phase 4 closeout curation (Archivist) inside `workspaces/ship-worktree/` and Phase 4 Edge 1 test-graduation verification inside `workspaces/actl-verify/` after the Implementer has passed all Phase 3 proofs.

### 1.6 Mechanical Edge Guards & Two-Stage Archivation Handoff

1. **Implementer → `actl` (Session Closure & Pre-Check Guards):** Guarded mechanically (solid line) before any Offline Run executes.


* **`actl` Pre-Flight Integrity Check:** `actl` (`verifier`) first verifies that the frozen `oracles/vN/` directory inside `actl-repo/` matches the immutable hash in `contract-vN.json`. A mismatch halts the runner immediately as a system integrity error (never consuming an Implementer retry).


* **Closure & Code Guards:** `actl` locks `handoff/{sprint}/closures/` to `chmod 0750`, increments `closures_submitted`, validates that `closure-NN.json` conforms to schema (`reason: done | blocked`, nullable `blocking_step`, `notes`, `backlog`, plus `closures_submitted` $\ge$ `min_attempts_before_block` and—when `solution_key_exposure: full`—structured `solution_key_divergence` for `reason: blocked`), natively fetches branch `wip/attempt-N` from `workspaces/wip-attempt-N/` (`chmod 2770 impl:actl`) into `workspaces/actl-verify/`, and checks `git diff {base_sha}..HEAD` against `ALLOW`/`FROZEN` scope (`scope.txt`), legacy test function count conservation (if any `test/{file}` was unfrozen in `scope.txt`), credential/secret leak scan, and forbidden-call lint. Every closure evaluation emits an `ev-NN.json` receipt. If any closure guard fails, `actl` emits a red `runs/ev-NN.json` citing the violated guard and routes it identically to a failed Offline Run (consuming 1 `retries_implementer` attempt and passing the guard failure in `prior_attempt.json`).




2. **Archivation Plan Hand-off (Split into Two Explicit Edges):** Because the Archivation plan undergoes both mechanical policy verification and semantic review, it is modeled as two separate edges:


* **Edge 1 — Archivist → `actl` (Solid Line / Script-Accepted):** `actl` enforces that `diff-risk-review.md`, `backlog-proposal.md`, and `plan/` (`NN-{slug}.patch` and `NN-{slug}.msg` pairs) exist and parse. `actl` (`verifier`) runs:


1. **Commit, Trailer & Disclosure Policy Check:** Validates subject format, required `Spec:` and `Oracle:` git trailers, matching `.patch`/`.msg` pairs, one `Graduated-Proof: {proof_script} → {test_file}::{test_name}` trailer in `NN-graduate-tests.msg` per `oracles/vN/proofs/*.sh` file, a mandatory `Waived Mutants & Residual Risk` section in `diff-risk-review.md` if any mutant was waived, and a mandatory `Modified Legacy Tests` section containing the verbatim `git diff {base_sha}..{contract-tag} -- test/` extract if any legacy test file was unfrozen in `scope.txt`.


2. **100% Feature Tree-Equality (`01 .. N-1`):** Ephemerally applies feature commits `01 .. N-1` in lexicographical order via `git apply --index && git commit -F` in `workspaces/actl-verify/` and verifies 100% bit-for-bit git tree-equality against `{contract-tag}` across all paths (`git diff {contract-tag} HEAD` is empty, with zero path exclusions).


3. **Unconditional Strictly New `test/**` Files on Commit N:** `NN-graduate-tests.patch` is unconditionally required on Commit N and must add $\ge 1$ strictly new file under `test/**` regardless of whether legacy tests were unfrozen and edited in `01 .. N-1`. `actl` applies `NN-graduate-tests.patch` and verifies that `git diff --name-only --no-renames --diff-filter=a {contract-tag} HEAD` is empty (where lowercase `a` excludes Added files so any non-added file status fails, and `--no-renames` prevents Git copy/rename heuristics from falsely flagging boilerplate) and all paths in `git diff --name-only {contract-tag} HEAD` match `test/**`.


4. **Anti-Slop Graduation Checks (Null-Base Red + Non-Vacuous Mutant-Kill Transfer + Full Test Pass):** Executed as `UID ship` in `workspaces/actl-verify/`:


* *(a) Null-Base Red Check:* Applying `NN-graduate-tests.patch` directly onto `base_sha` must fail (`exit` $\ne 0$). If it fails at collection/import/compile time (missing symbol from `01..N-1`), Check (b) must execute and kill 100% of non-waived mutants.


* *(b) Non-Vacuous Mutant-Kill Transfer Check:* Every killed mutant in `oracles/vN/mutants/*.patch` must either apply cleanly (`git apply --check`) onto Commit N or have a corresponding `archivation-plan/mutants-rebased/{name}.patch` (verified by `actl` to touch only production paths outside `test/**` and apply cleanly onto Commit N). Applying each mutant (original or rebased) and running the newly added test files must fail (`exit` $\ne 0$).


* *(c) Full Test Suite Pass:* Running the full repository Test suite on clean Commit N must pass (`exit 0`).






* **Edge 2 — `actl` → Owner (Dashed Line / Human-Accepted):** Once Edge 1 passes, `actl` sets `status: "hold"` in `state.json` and hands off the validated Archivation plan strictly to the human Owner (`approval_archivation_plan: owner`) for semantic review of `diff-risk-review.md`, `plan/`, and `backlog-proposal.md`. Automated rejections occur only on Edge 1 (`actl` verifier checks bounded by `retries_archivist`, escalating to the Owner on `retries_archivist_exhausted`). Human Owner revision requests on Edge 2 bypass budget limits entirely and re-invoke the Archivist with the Owner's specific change notes.

## 2. Core Vocabulary & Verification Concepts

| Term | Definition |
| --- | --- |
| **Proof** | A single executable script (`proofs/*.sh`) verifying a specific spec requirement. Exits `0` (pass) or `1` (fail). Must be stage-agnostic (switching between offline mock endpoints and live endpoints via injected environment variables, never conditional test branches). Unconditionally translated into new native test files in the target repository's `test/` directory by the Archivist during Phase 4 closeout.

 |
| **Oracle** | An artifact, not an actor. A frozen, hashed directory (`oracles/vN/`) inside `actl-repo/` containing `proofs/`, `probe.sh`, `scope.txt`, `solution_key.patch`, `mutants/`, `coverage.md`, and `oracle-critique.md`. `actl` stages a temporary copy into `workspaces/actl-verify/` during verification runs so `actl-repo/` remains `chmod 700`.

 |
| **Test** | The target repository's own tracked regression test suite (`test/`), including graduated proofs from prior specs. Executed automatically by `actl` during Phase 2 `oracle-qual-vN.json` (as `UID plan`), during every Phase 3 Offline Run (as `UID impl`, after `proofs/` and `probe.sh` pass), and during Phase 4 tree and mutant-kill verification (as `UID ship`).

 |
| **Guard** | A mechanical process check (file scope enforcement, legacy test function count conservation, credential leak scan, forbidden-call lint, commit message regex, git tree-equality). Proofs judge code; guards judge process.

 |
| **Actl (`actl`)** | The unified deterministic binary (`actl-repo/bin/actl`, composed of `orchestrator` [`state.py`], `dispatcher` [`dispatch.py`], and `verifier` [`verify.py`]) running under `UID actl` that manages `state.json`, supervises detached headless `tmux` agent sessions under `systemd` linger via `sudo -u {plan/impl/ship}`, enforces mechanical closure and archivation guards, executes Offline and Live verification runs (`runs/ev-NN.json`), and stamps `checklist.md` and `{contract-tag}`.

 |
| **Offline Run** | Full Phase 3 execution of the oracle (`proofs/` + `probe.sh` first, followed by the target repo's Test suite) by `actl` (running subprocesses as `sudo -u impl` inside `workspaces/actl-verify/` with private `/tmp` and post-run `pkill -9 -u impl`) after closure guards pass, with real credentials blanked.

 |
| **Live Run** | Phase 3 execution of the oracle (`proofs/` + `probe.sh`) against live external services, gated by `approval_live_run: "architect"` | `"owner"` (default `"architect"`) and executed via the root-owned privilege-dropping wrapper `/usr/local/bin/actl-live-run` (which verifies the Owner/Architect HMAC/decision, loads `/etc/actl/live.env` [`0400 root:root`] into memory, isolates execution via `unshare --pid --mount --fork --kill-child` with `setpriv --reuid=impl --regid=actl --init-groups`, and scrubs literal secrets before writing `runs/ev-NN.json`).

 |
| **Solution Key (`solution_key.patch`)** | A reference implementation patch authored solely by the Architect in Phase 1 (updated only by the Architect if Phase 2 qualification exposes a flaw), re-created by `actl` as `actl:plan` (`chmod 0440` inside `chmod 0750 plan-box/`) for Challenger audit, verified against Step 1 closure guards and Stage 2b repo Test during Phase 2 qualification, and copied into the Oracle directory at freeze where its canonical hash is locked. Proves satisfiability (Base = red, `solution_key.patch` = green) and serves as the Implementer's initial draft when `solution_key_exposure: full`. Never merged directly into the target repository without passing the Implementer, `actl`, and Archivist pipeline.

 |
| **Mutants** | Deliberately sabotaged patches (`mutants/*.patch`) written by the Challenger against `solution_key.patch` that violate a specific spec requirement to test whether the oracle catches them. ## 3. Personas, Authority & Independence Rules

### 3.1 Inter-Persona Context Isolation (Premise 7)

* **Premise 7 Formulation:** *"A persona may keep its own context across its own turns; what passes between personas is artifacts only."*

* Because Premise 7 restricts the communication channel between distinct personas rather than prohibiting a single persona from maintaining state across its own turns, the Architect's persistent thread (`architect_thread.jsonl`) across a spec's lifecycle is natively compliant. To preserve Premise 7 and POSIX file immutability between the Architect and Challenger (which both execute under OS `UID plan`), `actl` vaults `architect_thread.jsonl` and `architect-notes.md` inside `actl-repo/` (`chmod 700 actl:actl`), `unlink()`s the `plan`-owned `spec-vN.md` and `solution_key.patch` from `plan-box/`, and writes fresh copies owned by `actl:plan` (`chmod 0440`) whenever Challenger runs. Leaf personas (Challenger, Implementer, Archivist) run fresh per session under their dedicated Linux UIDs with static artifacts frontloaded by `actl` (`dispatcher`) for prompt-cache efficiency.

## 4. Standardized Artifact & Package Schemas

**Naming & Lifecycle Rules:**

* **Records** are structured data files emitted by an agent or `actl`.


* **Plans / Patches** are actionable bundles reviewed and applied during closeout.


* **Single Ownership of `solution_key.patch` & Adversarial Co-Evolution of `scope.txt`:** `solution_key.patch` is authored solely by the Architect in Phase 1 (and updated only by the Architect if Phase 2 qualification exposes a bug or spec refinement), re-created by `actl` as `actl:plan` (`chmod 0440` inside `chmod 0750 plan-box/`) while audited by the Challenger, verified against Step 1 closure guards and Stage 2b repo Test in `oracle-qual-vN.json`, and copied into `oracles/vN/` when locked by the Architect so its canonical hash is sealed at Oracle freeze. `scope.txt` is authored by the Challenger in Phase 2 and may be widened (`ALLOW` additions only) by the Architect during Phase 2 review or Phase 3 `action: "update_scope"` (with `actl` verifying that `proofs/`, `probe.sh`, `mutants/`, and `solution_key.patch` hashes remain 100% unchanged).


* **State vs. Epoch-Versioned Contract Separation:** `specs/{sprint}/runs/state.json` is initialized at Phase 1 start to track dynamic soft counters (`closures_submitted`, `retries_*`), hard watchdog counters (`hard_caps_tripped`), and active `tmux` sessions across all phases (scoped to `run_id`), whereas `specs/{sprint}/contract-vN.json` is minted once per contract epoch at Oracle vN freeze (entering Phase 3) and remains immutable throughout that epoch. Both `oracle-qual-vN.json` and `contract-vN.json` explicitly lock `base_sha`. If a Phase 3 escalation updates `scope.txt` (`action: "update_scope"`) or reopens the Oracle loop (`action: "reopen_oracle"`), `actl` mints `contract-vN+1.json` for the new epoch.


* **Evidence numbering:** `ev-NN` is a monotonic counter per spec in `specs/{sprint}/runs/`, emitted on every Phase 3 closure evaluation and never reset between runs or contract epochs.

### 5.1 State Persistence, Epoch-Immutable Contract & Supervisor-Backed Process Liveness (`actl`)

* **External State File (`specs/{sprint}/runs/state.json`) vs. Epoch-Immutable `contract-vN.json`:** `actl` (`orchestrator`) initializes `state.json` at the start of Phase 1 (scoped to `run_id` across any Spec vN revisions) to track runtime soft counters (`closures_submitted`, `retries_oracle`, `retries_implementer`, `retries_live`, `retries_archivist`), hard watchdog counters (`hard_caps_tripped`), active stage, `active_contract`, `status`, active `tmux` session metadata, and any dynamic retry increments granted during escalations. `contract-v1.json` is minted once when the Architect locks Oracle v1 (entering Phase 3) and is never mutated:


* If additional retries are granted on escalation (`action: "grant_retries"`) without changing the spec or oracle, `state.json` and `escalation-NN.json` (`resolution`) are updated while `contract-v1.json` remains static.


* If a Phase 3 escalation widens file scope (`action: "update_scope"`, using fast-path qualification) or reopens Phase 2 (`action: "reopen_oracle"`), `actl` generates `oracle-qual-vN+1.json`, mints `contract-vN+1.json` (which resets `closures_submitted` and `retries_implementer` to the new contract's baseline budget, requiring `retries_granted: 0` in `resolution`), and regenerates the requirement rows (`R_i`) of `checklist.md` from `oracles/vN+1/coverage.md` with `Offline Run` and `Live Run` reset to `open` (while preserving any `mutant/*.patch | waived` rows).


* If `state.json` is lost or corrupted, all soft and hard counters, active contract epochs, and grants can be deterministically reconstructed from `runs/oracle-qual-v*.json`, `runs/ev-*.json`, `escalation-NN.json` (via `resolution.retries_granted` and `minted_contract`), and the extended `sessions.tsv` ledger (`model`, `turns`, `tool_calls`, `tokens`, `cost_usd`, `accepted_items`, `closures_submitted`, `hard_caps_tripped`, `escalation_alerts_sent`).




* **Decoupled Headless `tmux` Supervision, Workspace Lifecycle & Anti-Wedge Liveness Tracking (`dispatch.py`):**
Process lifecycle supervision, workspace creation/teardown, state tracking, and console I/O are decoupled using daemonized headless `tmux` sessions backed by `systemd` user lingering (`loginctl enable-linger` enabled for `plan`, `impl`, and `ship`):


1. **Non-Root Workspace Creation & Teardown (`sudo -u {role_uid}` + `umask 0007`):** All `workspaces/{dir}/` clones are created and wiped via `sudo -u {role_uid}` with `umask 0007` enforced inside `{session}.run.sh` and `chmod 2770 {role_uid}:actl` on the root clone. This guarantees `actl` (a member of groups `plan`, `impl`, and `ship`) has full group read/write access to all nested directories and can execute clean `sudo -u {role_uid} rm -rf` teardown without `EPERM` or `EACCES`.


2. **Decoupled Process Tree (No Orphaned Children):** Agent sessions are never spawned as naked subprocesses of the caller's terminal. `dispatch.py` spawns each session inside a dedicated headless `tmux` session (`spawn_detached_session`). If the caller CLI or SSH session disconnects or crashes, the runner process continues unaffected inside `tmux` under `systemd` linger.


3. **Supervisor-Backed Liveness Over Raw PIDs/PGIDs:** Instead of storing fragile Linux PIDs/PGIDs in `state.json`, liveness is evaluated dynamically via `list_active_tmux_sessions()`, which polls `sudo -u {uid} tmux list-sessions -F "#{session_name}|#{session_created}"`.


4. **Automatic Stale-State Pruning (Anti-Wedge):** Whenever sessions are queried or re-inspected (`get_running_sessions`), `actl` cross-references disk metadata against active `tmux` sessions. Any metadata entry corresponding to a dead session is immediately unlinked (`meta_file.unlink()`), and `actl` reconciles transition state from the completed session artifacts without wedging or double-spending retry budgets.


5. **Self-Terminating Ephemeral Runners:** Each session executes inside a dynamically generated runner script (`{session}.run.sh`) with `umask 0007`, an explicit `EXIT` trap (`trap cleanup EXIT`), and `remain-on-exit off`. When the process exits—whether by normal completion, fatal error, or `timeout -k 15s {wall_clock}` watchdog—the runner automatically cleans its active session metadata and terminates the `tmux` socket so it can never remain stuck in a zombie running state.


6. **Non-Destructive Attaching & Detaching:** Interactive observation (`actl attach {session}`) operates via a streaming tail proxy (`stream_session`) over `pipe-pane` log streams. Pressing `Ctrl+C` does not send `SIGINT` to the agent child; instead, Python traps `KeyboardInterrupt`, preserves background execution, and presents an interactive menu (`[b] Detach to shell`, `[r] Resume stream`, `[k] Kill session`).





### 5.2 Adversarial Oracle Qualification Loop (Architect ↔ `actl` ↔ Challenger)

1. **Adversarial Authoring & Mechanical Qualification:**
* **Architect Spec & Reference Key (Inode Re-Creation):** In Phase 1, following interactive Q&A with the Owner, the Architect (`sudo -u plan`) authors `spec-v1.md` and `solution_key.patch` in `plan-box/`. After every Architect turn, `actl` (`UID actl`) vaults `architect_thread.jsonl` and `architect-notes.md` into `actl-repo/`, promotes `spec-vN.md` and `solution_key.patch` into `actl-repo/specs/{sprint}/`, `unlink()`s the `plan`-owned originals from `plan-box/`, and writes fresh copies owned by `actl:plan` (`chmod 0440`) inside `chmod 0750 plan-box/`. Because `actl` owns the directory and the new inodes, POSIX forbids `UID plan` (Challenger) from running `chmod`, modifying, or `unlink()`ing either file.


* **Challenger Audit, Oracle Authoring & Critique:** In Phase 2, the cross-family Challenger (`sudo -u plan`) audits read-only `spec-v1.md` and `solution_key.patch` for semantic flaws (missing requirement coverage, shared misreadings, weak assertions such as checking `has("email")|not` when an email leaks under a renamed key `contact`) and authors `oracle-draft/` (`proofs/`, `probe.sh`, `mutants/`, `scope.txt`, `coverage.md`, plus `oracle-critique.md`) inside `plan-box/oracle-draft/` (`chmod 0770`). By default, `scope.txt` sets `FROZEN: test/**`.


* **Mechanical Qualification & Diagnostic Classification (`oracle-qual-vN.json`):** `actl` (`verifier`) stages `oracle-draft/` and `actl-repo/`'s canonical `solution_key.patch` into `workspaces/actl-verify/` and runs it under `UID plan` against `base_sha`, verifying five checks:


1. The null base implementation at `base_sha` fails `proofs/` (`null_base: red`),


2. `solution_key.patch` passes Step 1 Closure Guards (`scope.txt`, secret scan, forbidden-call lint) (`solution_key_guards: green`),


3. `solution_key.patch` passes `proofs/` and `probe.sh` repeatedly (`solution_key_green: 3/3`),


4. `solution_key.patch` passes Stage 2b (the target repo's existing Test suite) (`solution_key_repo_test: green`)—catching any obsolete existing test in Phase 2 so the Architect can update `solution_key.patch` and surgically add `ALLOW: test/{specific_file}` to `scope.txt`, and


5. **Mutant Evaluation (Gated on `solution_key_green`):** Evaluated only if `solution_key_guards == "green"` and `solution_key_green == "3/3"` (`skipped` otherwise, preventing false `killed: true` results from a broken `solution_key.patch`). A mutant is `killed: true` iff `git apply` succeeds on `base_sha + solution_key.patch` AND at least one proof (or `probe.sh`) exits `1`. Any mutant that fails `git apply` stamps `killed: false, apply_error: true`.




* Based on those five checks, `actl` stamps `diagnostic_case` in `oracle-qual-vN.json`:


* `"none"`: All five qualification checks passed (`null_base: red`, all `solution_key_*` checks green, and all mutants `killed: true` with `apply_error: false`).


* `"pure_oracle_failure"`: All `solution_key_*` checks are green (the Architect's solution key passed everything), but `null_base == "green"` or at least one mutant has `killed: false` (survived or `apply_error: true`), proving the Challenger's Oracle assertions or mutants need strengthening.


* `"solution_key_conflict"`: Any `solution_key_*` check is red (a Challenger proof, `scope.txt` rule, or existing repo Test rejected the Architect's `solution_key.patch`).






2. **Four-Layer Defense Against Weak Proofs:**
* **Value-level sentinel proofs:** Seed known sentinel strings (e.g., a test email) and fail if the literal string appears anywhere in the raw response payload.


* **End-to-end probe (`probe.sh`):** Inspects actual runtime outputs and performs independent recomputation.


* **Adversarial mutants:** Challenger supplies sabotaged patches (`mutants/contact_leak.patch`) that expose weak assertions and remain archived in `oracles/vN/mutants/` for Phase 2 and Phase 4 verification.


* **Visible residual risk & Owner disclosure:** Any surviving mutant (`killed: false`) waived at escalation (recorded in `escalation-NN.json` `resolution.waived_mutants`) is stamped as a dedicated `mutant/{name}.patch | waived | escalation-NN` row in `checklist.md` and must be explained in `diff-risk-review.md` for Owner review at closeout.




3. **Architect Review, Locking Authority & Loop Governance:**
After generating `oracle-qual-vN.json` (on every round, including when `retries_oracle` remaining is `0`), `actl` restores `architect_thread.jsonl` and `chmod 0770` on `plan-box/` and invokes the Architect to review `oracle-critique.md` and `oracle-qual-vN.json`. The Architect writes `plan-box/oracle-decision.json` (`decision: "lock_oracle" | "revise_oracle"`):


* **Path 1 — Lock Proofs (`decision: "lock_oracle"`):**
* **When `diagnostic_case == "none"`:** If the Architect agrees with the Challenger's proofs and critique, `actl` immediately freezes `oracles/vN/` into `actl-repo/` (locking the canonical hash of `solution_key.patch`) and mints `contract-v1.json`.


* **When `diagnostic_case == "solution_key_conflict"` (Challenger Caught a Flaw in `solution_key.patch` or `scope.txt`):** If the Architect agrees with the Challenger's critique and fixes `solution_key.patch` (and/or widens `ALLOW` in `scope.txt`) without needing changes to `proofs/` or `mutants/`, the Architect emits `decision: "lock_oracle"`. `actl` immediately re-runs `oracle-qual-vN+1.json` without spending a Challenger turn; if `diagnostic_case` is now `"none"`, `actl` freezes the Oracle and mints `contract-v1.json` (otherwise, if a mutant now fails with `apply_error: true` or survives, it routes as `revise_oracle`).




* **Path 2 — Return to Challenger (`decision: "revise_oracle"`):**
* **On `pure_oracle_failure` or Disagreed `solution_key_conflict`:** If a mutant survived or failed to apply (`pure_oracle_failure`), or if the Challenger's proof/scope rule was over-strict (`solution_key_conflict`), or if the Architect refined `spec-vN.md` in response to `oracle-critique.md`, the Architect records her directive in `oracle-decision.json` (`decision: "revise_oracle"`, `feedback: "..."`). While `retries_oracle` budget remains, `actl` re-creates `spec-vN.md` and `solution_key.patch` as `actl:plan` (`chmod 0440`) inside `chmod 0750 plan-box/` and dispatches the Challenger (`retries_oracle` consumed) to revise `oracle-draft/`.




* **When `retries_oracle` Runs Out (`trigger: retries_oracle_exhausted`):** Fires only when the Architect emits `decision: "revise_oracle"` (or a `lock_oracle` re-qualification still fails) and `retries_oracle` remaining is `0`. `actl` assembles `escalation-NN.json` (with `oracle_review` populated from the latest `oracle-qual-vN.json`, including `diagnostic_case`, `failing_checks`, and `surviving_mutants`) and routes it via `actl` → Architect (or `actl` → Owner if `mutant_waiver_authority: owner`). To preserve cross-family independence (**F**), the Architect never edits `proofs/` or `mutants/` directly; the authority records `resolution` in `escalation-NN.json`, choosing:


1. Grant additional `retries_oracle` budget in `state.json` (`action: "grant_retries"`), or


2. Waive the surviving mutant(s) (`action: "waive_mutant"`, governed by `mutant_waiver_authority: architect | owner`, default `architect`), which `actl` mechanically accepts only when `oracle_review.failing_checks` is empty (`null_base == "red"` and all `solution_key_* == "green"`): the latest oracle freezes, `actl` mints `contract-v1.json` (stamping `minted_contract`), and appends `mutant/{name}.patch | waived | escalation-NN (sha256: ...)` rows in `checklist.md`.







### 5.3 Coverage Map & Checklist Stamping Rule

* `coverage.md` explicitly lists every proof ID (plus `probe.sh`) required to satisfy each requirement (`R_i` → `[proof_a, proof_b, ..., probe.sh]`).


* `specs/{sprint}/checklist.md` tracks `Offline Run` and `Live Run` receipts in separate columns, recording both the `ev-NN.json` SHA-256 hash and the literal head commit SHA evaluated:


* When `live_run: none`, the `Live Run` column is initialized to `n/a`, and `actl` stamps each `R_i` row `Status: done` once all mapped `proofs/`, `probe.sh`, and the target repo's Test suite exit `0` (green) in the composite `Offline Run` receipt (`ev-NN.json`) on the same head commit SHA.


* When `live_run: required`, `Status` remains `open` after the `Offline Run` column is populated and only flips to `done` when the `Live Run` column also records `0` (green) receipts for all mapped `proofs/` and `probe.sh` on the identical head commit SHA.


* Once all required Phase 3 runs (`Offline Run` and, if required, `Live Run`) pass on that identical head commit SHA, `actl` creates/updates the internal git tag `refs/tags/actl/{sprint}/{contract-vN-sha256}` (`{contract-tag}`) in `repos/target-repo/.git` pointing to that head SHA before invoking the Archivist in Phase 4.


* Surviving mutants waived in Phase 2 occupy their own `mutant/{name}.patch | waived | escalation-NN` rows and never mark a requirement row (`R_i`) as `done` or `waived`.


* Closeout requires zero `open` requirement rows in `checklist.md` (every `R_i` row must be `done`, and any `waived` mutant rows must be disclosed in `diff-risk-review.md`).





### 5.4 Implementation Routing, Retries & Blocked Escalations

1. **Standalone Clone & Retry / Restart Mechanics:** For each attempt $N$, `actl` (`dispatcher`) creates a fresh standalone local clone (`sudo -u impl git clone --local --no-hardlinks repos/target-repo workspaces/wip-attempt-N`, owned by `impl:actl`, `chmod 2770`, `umask 0007`), sets `handoff/{sprint}/closures/` to `chmod 0770`, and launches a fresh Implementer session (`sudo -u impl`, frontloading static prefixes + `solution_key.patch` when `full`) checked out at `base_sha` on branch `wip/attempt-N`. The Implementer commits work incrementally onto `wip/attempt-N` for full traceability. When the Implementer writes `closure-NN.json`, `actl` (`verifier`) locks `handoff/{sprint}/closures/` to `chmod 0750`, increments `closures_submitted`, and natively fetches `wip/attempt-N` into `workspaces/actl-verify/` to evaluate closure guards and the Offline Run, emitting an `ev-NN.json` receipt for every closure evaluation. When an `actl` closure guard or Offline run is red and `retries_implementer` budget remains, `actl` deletes `workspaces/wip-attempt-N/` via `sudo -u impl rm -rf`, creates a clean standalone clone `workspaces/wip-attempt-N+1/` at `base_sha`, and writes `prior_attempt.json` (previous diff patch, `failing_step` and `failing_line` from the last `ev-NN.json`, and `closures_submitted` count) to `handoff/{sprint}/work-order/` strictly as an optional hint. `log_tail` from Escalation records goes to the Architect only and is never forwarded to a later Implementer.


2. **Deterministic Routing on Closure `reason`:**
* **`reason: done`** → Triggers `actl` Step 1 Pre-Flight & Closure Guards followed immediately by the Step 2 Fail-Fast Offline Run (§5.5).


* **`reason: blocked`** → Implementer halts when it cannot satisfy `actl` verification due to an `ALLOW` scope restriction (including an obsolete existing test in `FROZEN: test/**`), missing architectural decision, or suspected over-constrained proof (`blocking_step` cites the deterministic `steps[].cmd` ID from `ev-NN.json`, e.g., `"guard:scope"`, `"bash proofs/02_no_email.sh"`, or `"test:{name}"`, or `null` on a pure architectural block).


* **Anti-Early-Give-Up Guards:** When `closure-NN.json` specifies `reason: blocked`, `actl` executes Step 1 Closure Guards and Stage 2b (Test) directly against the current worktree (emitting `ev-NN.json`) and mechanically rejects `reason: blocked` (treating an invalid `blocked` claim as a failed attempt that consumes 1 `retries_implementer` credit) unless:


1. `closures_submitted` $\ge$ `min_attempts_before_block`,


2. All Step 1 mechanical `ALLOW`/secret/lint closure guards pass on the current worktree (unless `blocking_step == "guard:scope"`) and the target repository's own compilation and Stage 2b Test suite pass on the current worktree (unless `blocking_step` explicitly cites a failing `test:{name}` step), and


3. When `solution_key_exposure: full`, `closure-NN.json` includes a non-null structured `solution_key_divergence: {"requirement_id": "{R_i}", "rationale": "{non-empty string}"}` where `requirement_id` is mechanically verified to exist in `oracles/vN/coverage.md` (explaining which spec requirement or constraint `solution_key.patch` shortcutted).




* **Phase 3 Obsolete-Test Escape Hatch (`FROZEN: test/**`) & Surgical Test-Diff Audit Gate:** If an existing regression test in `test/**` fails during Phase 3 because it conflicts with new spec behavior and was not unfrozen in Phase 2, the Implementer cannot edit `test/**` directly (`FROZEN: test/**`). Instead, the Implementer halts with `reason: blocked` and `blocking_step: "test:{name}"`. `actl` routes `escalation-NN.json` (`trigger: blocked`) to the Architect, who inspects the test failure and resolves via `action: "update_scope"`—surgically adding `ALLOW: test/{specific_file}` to `oracles/vN+1/scope.txt`. Whenever any `ALLOW: test/{file}` rule is active in `scope.txt`, `actl` enforces that the count of discovered test functions (`test_*`) in `test/{file}` never decreases relative to `base_sha` (unless explicitly pre-authorized in `scope.txt`), and attaches the verbatim `git diff {base_sha}..HEAD -- test/` extract to both Phase 3 Live Run approval and Phase 4 `diff-risk-review.md` (`Modified Legacy Tests`).


* **Escalation Routing:** Once `blocked` preconditions are met, `actl` assembles `escalation-NN.json` (`trigger: blocked`, citing `last_closure` and `evidence`) and routes it via `actl` → Architect. The Architect inspects `escalation-NN.json` in its persistent thread and records `resolution` in `escalation-NN.json`:


1. **`action: "update_scope"` (`retries_granted: 0`, Fast-Path Qualification):** Architect updates `scope.txt` in `plan-box/oracle-draft/`; `actl` mechanically verifies that: (a) `proofs/`, `probe.sh`, `mutants/`, and `solution_key.patch` hashes are 100% identical to `oracles/vN/`, (b) `scope.txt` contains no blanket `ALLOW: **` or `ALLOW: test/**` globs and passes `guard:scope` in-memory against both `solution_key.patch` and—when `blocking_step == "guard:scope"`—the Implementer's `wip/attempt-N` diff, and (c) **zero test suites are re-executed**: `actl` carries forward the invariant `null_base`, `solution_key_green`, `solution_key_repo_test`, and `mutants` results from `oracle-qual-vN.json`, stamps the new `manifest_sha256` into `oracle-qual-vN+1.json`, and mints `contract-vN+1.json` with a fresh baseline retry budget.


2. **`action: "reopen_oracle"` (`retries_granted: 0`):** If a proof in `proofs/` or `spec-vN.md` itself requires revision, the Architect reopens the Phase 2 Architect ↔ `actl` ↔ Challenger loop to produce and lock `oracles/vN+1/` and mint `contract-vN+1.json`.


3. **`action: "grant_retries"`:** Rejects the block and grants additional `retries_implementer` budget in `state.json`.


4. **`action: "escalate_owner"`:** Escalates to the human Owner via `actl` → Owner (`status: "hold"`) if product intent must change.




* **Intra-Session Hard-Cap Termination (`trigger: hard_cap_exhausted`):** If a session is killed mid-execution by the wall-clock supervisor (`timeout -k 15s`) or supported native turn/token/cost hard caps before emitting a closure, `actl` increments `hard_caps_tripped` (leaving `closures_submitted` unchanged), synthesizes `escalation-NN.json` (`trigger: hard_cap_exhausted`) from `state.json`, and routes it via `actl` → Architect.





### 5.5 Phase 3 Verification: Closure Guards, Fail-Fast Offline Run & Gated Live Run

1. **Step 1 — `actl` Pre-Flight & Self-Tested Mechanical Closure Guards (Before Offline Run):**
* **Oracle Pre-Flight Hash Check:** `actl` (`verifier`) verifies `actl-repo/specs/{sprint}/oracles/vN/` against `contract-vN.json` (halting on corruption without consuming an Implementer retry).


* **Closure Guards:** Upon Implementer → `actl` closure, and before executing untrusted Implementer code, `actl` locks `handoff/{sprint}/closures/` to `chmod 0750`, validates `closure-NN.json`, fetches `wip/attempt-N` into `workspaces/actl-verify/`, checks `git diff {base_sha}..HEAD` against `ALLOW`/`FROZEN` scope (`scope.txt`), verifies legacy test function counts if any `test/{file}` was unfrozen, runs the credential/secret leak scan, and runs the forbidden-call lint.


* **Mandatory Self-Tests:** Every guard/scanner must pass its own built-in self-test (verifying it catches known synthetic leaks and forbidden calls) before evaluating the worktree so a broken lint cannot silently pass before reaching Live Run approval.




2. **Step 2 — Fail-Fast Offline Run (`proofs/` First, Repo Test Second, Executed as `UID impl`):**
Once Step 1 guards are green, `actl` checks out the candidate commit in `workspaces/actl-verify/`, stages a temporary copy of `oracles/vN/` readable by `impl`, and spawns the verification runner as `sudo -u impl` with a private `/tmp` (`unshare -p --kill-child` / `PrivateTmp=yes`) and credentials blanked:


* **Stage 2a (Fast Feature Check):** Executes the Oracle's `proofs/*.sh` and `probe.sh` first so feature errors fail fast within seconds.


* **Stage 2b (Regression Armor):** Immediately executes the target repository's existing Test suite (`test/`) to guarantee zero regressions against prior specs.


* **Post-Run Cleanup:** Regardless of exit code, `actl` runs `sudo -u impl pkill -9 -u impl`, deletes the staged Oracle copy, and wipes the private `/tmp` so no background process spawned during testing survives into later runs.


* When both Stage 2a and Stage 2b exit `0`, `actl` writes the composite green `runs/ev-NN.json` (`steps[]`) and stamps the `Offline Run` column (with `ev-NN` hash and head SHA) in `checklist.md`.




3. **Step 3 — Gated Live Run (`approval_live_run: architect | owner`, Default `architect`):**
Governed by `live_run: none | required` and `approval_live_run: architect | owner` (unattended `"auto"` approval is prohibited):


* **Authority Gate (Post-Offline Green):** Once Step 2 (Offline Run) exits `0` on `{head_sha}`, `actl` pauses before injecting live secrets:


* When `approval_live_run: architect`: At Phase 1 close, the Owner pre-signs a sprint delegation token (`specs/{sprint}/live-delegation.hmac` over `sprint_id || base_sha || "architect"` using `/etc/actl/owner.key`). After Step 2 passes, `actl` invokes the Architect with the green Offline `ev-NN.json` and candidate diff (`git diff {base_sha}..{head_sha}`, plus `Modified Legacy Tests` diff if any `test/{file}` was unfrozen). The Architect emits `plan-box/live-decision.json` (`decision: "approve_live" | "reject_live"`, `head_sha`), which `actl` promotes to `specs/{sprint}/runs/live-decision.json`.


* When `approval_live_run: owner`: `actl` sets `status: "hold"` and notifies the Owner, who reviews the diff and signs `specs/{sprint}/runs/live-decision.hmac` over `sprint_id || contract_sha256 || head_sha`.




* **Root-Owned Privilege-Dropping Wrapper (`/usr/local/bin/actl-live-run`):** Live credentials are stored in `/etc/actl/live.env` (`owner: root:root`, `chmod 0400`) and the Owner's HMAC verification key in `/etc/actl/owner.key` (`owner: root:root`, `chmod 0400`)—never inside any agent UID or human owner home directory. `actl` is granted a narrow sudoers rule (`actl ALL=(root) NOPASSWD: /usr/local/bin/actl-live-run`). `actl` invokes `sudo /usr/local/bin/actl-live-run {sprint} {head_sha}`, which:


1. Verifies either (`live-delegation.hmac` against `/etc/actl/owner.key` + `live-decision.json` matching `{head_sha}`) when `architect`, or `live-decision.hmac` against `/etc/actl/owner.key` when `owner` (exiting `1` on mismatch),


2. Loads the allowlisted secret environment variables from `/etc/actl/live.env` into process memory, and


3. Executes inside `unshare --pid --mount --fork --kill-child` (mounting a private `/tmp`) and drops privileges permanently via `setpriv --reuid=impl --regid=actl --init-groups` to execute the stage-agnostic `proofs/*.sh` and `probe.sh` inside `workspaces/actl-verify/`, followed by post-run `sudo -u impl pkill -9 -u impl` and `actl-verify/` cleanup. Because `~impl` is provisioned read-only (`root:impl`, `chmod 0750`) and `handoff/{sprint}/closures/` is locked to `chmod 0750`, `UID impl` has zero persistent writable paths across runs.




* **Secret Scrubbing & Failure Routing (`trigger: "live_run_failed"`):** `actl-live-run` replaces any literal value present in `/etc/actl/live.env` with `[REDACTED]` before emitting `runs/ev-NN.json`. If a Live Run exits $\ne 0$, `actl` sends an immediate non-blocking alert to the Owner and routes `escalation-NN.json` (`trigger: "live_run_failed"`, bounded by `retries_live`, default `1`) to the **Architect** (never directly to the Implementer). The Architect attempts a single recovery cycle (`reopen_oracle` or `grant_retries`); if a subsequent Live Run fails after `retries_live` is exhausted, `actl` halts (`status: "hold"`) and awaits the Owner.


* When green, `actl` stamps the `Live Run` column (verifying the head SHA matches the `Offline Run` column), marks requirement rows `Status: done` in `checklist.md`, and pins `refs/tags/actl/{sprint}/{contract-vN-sha256}` (`{contract-tag}`) in `repos/target-repo/.git`.





### 5.6 Phase 4 Closeout: Archivist Curation, Anti-Slop Proof Graduation & Owner Push (`UID ship`)

1. **Step 1 — Archivist Curation & Proof-to-Test Graduation (`UID ship`):**

## 6. Dynamic Budget & Escalation Functions

### 6.1 Intra-Session Hard Caps (`hard_cap`) vs. Inter-Session Soft Loop Counters (`retries_*`)

Resource and iteration ceilings are partitioned into two orthogonal classes resolved at Phase 1 start into `state.json` and locked into `contract-vN.json` at Phase 3 Oracle freeze:

```text
effective_limit(dimension, contract_or_state, context) -> (limit, mechanism, on_exceed)

```

1. **Intra-Session Hard Caps (`hard_cap` → increments `hard_caps_tripped` → triggers `hard_cap_exhausted`):**
* Govern a single CLI invocation: `wall_clock` (`timeout -k 15s {limit}` inside `{session}.run.sh`), `turns`, `tool_calls`, `tokens`, and `cost_usd`.


* **Orthogonal Watchdog Counter (`hard_caps_tripped`):** When a session is terminated mid-execution by `wall_clock` or a native engine flag before emitting a handoff artifact (`last_closure: null`), `actl` increments `hard_caps_tripped` without incrementing `closures_submitted` or satisfying `min_attempts_before_block`, and immediately routes `escalation-NN.json` (`trigger: "hard_cap_exhausted"`) to the Architect.


* **Native Enforcement & Fail-Closed Compatibility Halt (MVP):** Whenever a CLI engine natively supports a configured `hard_cap` dimension, `dispatch.py` passes and enforces the native flag directly. If a contract or configuration specifies a non-null `hard_cap` dimension (e.g., `turns`, `tool_calls`, `tokens`, or `cost_usd`) and the target persona's CLI adapter cannot confirm native enforcement support, `actl` refuses to start the session (fail-closed), writes `status: "hold"` to `state.json`, and notifies the Owner/user identifying the exact unsupported `(cli_engine, dimension)` pair so the user can either set that dimension to `null` (relying on `wall_clock` + post-run `sessions.tsv` telemetry) or switch the persona's CLI engine.


* **Post-MVP Roadmap Note (Stream-Parsed Hard Caps):** In a post-MVP release, `dispatch.py` will add real-time JSONL/`pipe-pane` stream monitoring to enforce `turns`, `tool_calls`, `tokens`, and `cost_usd` via `SIGTERM`/`SIGKILL` across CLI engines that lack native flags without halting on startup.


* **Sub-Agent Spawner Prohibition:** Every CLI adapter mechanically disables native in-process sub-agent tools (`AgentTool` / sub-task spawners) so no persona can spawn an in-process child agent inside the same UID. Every persona transition must return to `actl`.


* **Universal Wall-Clock & `tmux` Supervisor:** Every CLI engine executes inside a detached headless `tmux` session (`spawn_detached_session` under `loginctl enable-linger`) wrapped in `{session}.run.sh` with `umask 0007`, `timeout -k 15s {limit}`, `remain-on-exit off`, and `trap cleanup EXIT`.




2. **Inter-Session Soft Loop Counters (`closures_submitted` / `retries_{stage}` → triggers `retries_{stage}_exhausted`):**
* Count completed sessions that emitted a valid handoff artifact (`oracle-draft/`, `closure-NN.json`, `archivation-plan/`) for the active contract in `state.json`:


* `retries_oracle` → `retries_oracle_exhausted` (counts `revise_oracle` loop-backs dispatched to the Challenger in Phase 2; the Architect always gets her post-qualification review turn before exhaustion fires).


* `retries_implementer` → `retries_implementer_exhausted` (Phase 3 Implementer ↔ `actl` implementation loop, paired with `closures_submitted` $\ge$ `min_attempts_before_block`).


* `retries_live` → halts to Owner (`status: "hold"`) if a subsequent Phase 3 Live Run fails after the Architect's `live_run_failed` recovery cycle (default `1`).


* `retries_archivist` → `retries_archivist_exhausted` (Phase 4 automated `actl` mechanical rejections on Edge 1; human Owner revisions on Edge 2 are uncapped).

### 6.3 Dynamic Escalation Policy Function

Escalation routing resolves dynamically across all four phases (reading `state.json` in Phases 1–2 and `contract-vN.json` + `state.json` in Phases 3–4):

```text
escalation_policy(event, contract_or_state, context) -> decision (logged with inputs)

```

* **Inputs:** Event type (`retries_oracle_exhausted`, `retries_implementer_exhausted`, `retries_archivist_exhausted`, `live_run_failed`, `hard_cap_exhausted`, `blocked`), risk tier, `mutant_waiver_authority`, time of day, and Owner availability.


* **Two-Tier Routing (`actl` → Architect then `actl` → Owner):** By default, `actl` routes `retries_oracle_exhausted`, `retries_implementer_exhausted`, `live_run_failed` (with an immediate parallel alert to the Owner), `hard_cap_exhausted`, and `blocked` to the Architect first. `actl` routes directly to the human Owner (via the Notification Adapter) when:


1. The Architect explicitly escalates an unresolved spec/scope/mutant decision to the Owner (`resolution.action: "escalate_owner"`),


2. The synchronous Architect session itself fails or hits `hard_cap_exhausted`,


3. A subsequent Live Run fails after `retries_live` is exhausted,


4. `retries_archivist_exhausted` triggers in Phase 4,


5. An unsupported `(cli_engine, hard_cap_dimension)` pair triggers the fail-closed adapter guard on startup, or


6. `escalation_policy()` requires direct Owner authority (e.g., `mutant_waiver_authority: owner` or high risk tier).




* **Safe Default on No Response (`hold`):** Availability windows, time-of-day routing, and `escalation_alerts_sent` apply strictly when targeting the human Owner. If an Owner escalation receives no response within the availability window (or if a synchronous Architect invocation fails), the mandatory safe default is **`hold`** (write `status: "hold"` in `state.json` and await human Owner intervention)—never auto-approve.


* **Hold scope:** `hold` applies strictly to the actionable party's decision; an unanswered informational Owner notification (such as the initial parallel alert on `live_run_failed` while `retries_live` remains) never blocks a run that the Architect is authorized to resolve.
